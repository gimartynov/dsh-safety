# dsh-guard

Детерминированная защита от разрушительных действий агента. Никаких вызовов модели:
одна синхронная проверка строки команды и путей на каждый вызов инструмента, поэтому
плагин не добавляет ни токенов в промпт, ни запросов к провайдеру.

## Что делает

На каждый вызов инструмента (сразу после стадии подтверждения) плагин решает одно из трёх:

| Решение | Когда |
| --- | --- |
| **deny** | команда реально пишет в защищённый путь (`rm`, `mv`, `cp`, `sed -i`, `tee`, редирект…) или совпала с катастрофическим шаблоном |
| **ask** | команда может переписать историю git (`git reset --hard`, `git clean -fd`, `git push --force`, `git stash drop`, `git checkout -- .`) или уничтожить дерево (`rm -r`, `shred`, `truncate -s 0`) |
| **allow** | всё остальное, включая любые чтения: `cat`, `ls`, `grep`, `read`, `glob` по защищённым путям не блокируются |

Учитываются только пути, с которыми работает разрушительный глагол. Упоминание пути в тексте
не блокирует вызов: `grep -rn 'rm -rf ~/Notes' .` и скрипт внутри heredoc проходят — тело heredoc
считается данными, а не командой.

`deny` возвращается в монотонный слой `ctx.tools.guard()`: решение окончательное, агент получает
причину отказа текстом. `ask` поднимается на водопаде `tools/pre-execute` как обычный запрос
подтверждения — человек видит его в той же панели, что и встроенные подтверждения.

Защищённые пути по умолчанию: `~/.dsh`, `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config/gh`,
`~/Library/Keychains`. Свои пути добавляются в конфиге.

## Конфиг

```yaml
# ~/.dsh/profiles/<profile>/cordis.patch.yml
- id: dsh-guard
  config:
    protect:
      - '~/Games/MyGame'   # игра: агент не тронет ни dist, ни исходники
      - '~/Desktop/Books'      # книги
      - '~/Documents/deepseek-harness/default-workspace/.env'
    allowWrite:
      - '~/Games/MyGame/web' # исключение: сюда писать можно (деплой)
    protectSystem: true
    auditFile: '~/.dsh/guard-audit.jsonl'
```

| Ключ | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `protect` | `string[]` | `[]` | дополнительные защищённые пути, `~` раскрывается |
| `allowWrite` | `string[]` | `[]` | поддеревья внутри защищённых путей, куда писать разрешено |
| `protectSystem` | `boolean` | `true` | защищать ли системные пути (`~/.dsh`, `~/.ssh`, …) |
| `denyPatterns` | `string[]` | катастрофические | регулярные выражения (без учёта регистра) — отказ независимо от путей |
| `askPatterns` | `string[]` | git-история | регулярные выражения — запрос подтверждения |
| `auditFile` | `string` | `~/.dsh/guard-audit.jsonl` | журнал отказов и запросов; `''` отключает |
| `caseInsensitive` | `boolean` | `true` | сравнение путей без учёта регистра (macOS); на Linux с регистрозависимой ФС — `false` |

## Как читается журнал

```bash
tail -5 ~/.dsh/guard-audit.jsonl
# {"at":"…","action":"deny","tool":"bash","reason":"dsh-guard: \"~/Games/MyGame/dist\" is inside a protected path …"}
```

## Ограничения

- Разбор bash — эвристика по строке, а не разбор оболочки: путь, собранный из переменных или
  base64, проверка не увидит. Защита в глубину по-прежнему держится на песочнице DSH
  (`workspace-write`) и на подтверждениях.
- Относительные цели разрешаются только при явном `cwd` в аргументах вызова: каталог оболочки
  иначе неизвестен, и угадывать его плагин не пытается (лучше пропустить проверку, чем отказать
  в невинной команде). Если `cwd` — защищённый каталог, а явных целей нет, вызов отклоняется.
- Тело heredoc игнорируется при поиске целей и катастрофических шаблонов: документ или чужой
  скрипт с текстом `rm -rf /` внутри не считается командой. Цена — путь, собранный из переменных
  внутри heredoc, тоже не виден.
- Инструменты записи (`write`, `edit`, `str_replace_editor`) проверяются по полям
  `file_path` / `path` / `target_file` / `filePath` / `target`.
- Плагин не трогает встроенные пресеты прав и не подменяет `danger-full-access`:
  он добавляет ещё один независимый слой.

## Установка

```bash
dsh plugin add /path/to/dsh-guard   # или: Settings → Plugins → Install bundle
```

После установки нужен один перезапуск приложения.
