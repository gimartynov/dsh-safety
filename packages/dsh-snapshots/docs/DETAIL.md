# dsh-snapshots

Локальные точки восстановления для проекта. Теневой git-репозиторий лежит в
`~/.dsh/snapshots/`, а ваш собственный `.git` не трогается: снапшоты не появляются
в истории проекта и не уезжают ни на какой сервер. Модель не вызывается — токенов ноль.

## Зачем

Встроенная карточка «изменённые файлы» в DSH показывает правки за ход, но её объекты живут
временем сессии и удаляются вместе с ней. Этот плагин держит постоянные точки, к которым
можно вернуться хоть через неделю.

## Команды

| Команда | Что делает |
| --- | --- |
| `/snap [метка]` | снять снапшот всех настроенных проектов; без изменений — пишет «no changes» |
| `/snapshots [N]` | список последних N точек (по умолчанию 10): номер, время, метка |
| `/rollback <номер\|ref> [--clean]` | вернуть файлы из точки; `--clean` дополнительно удаляет файлы, созданные после неё |

Перед каждым откатом плагин сам снимает `pre-rollback`-снапшот, поэтому сам откат
тоже обратим.

Автоматически: перед первым изменяющим вызовом (`rm`, `mv`, `cp`, `sed -i`, `git reset`…,
а также `write`/`edit`) снимается снапшот с меткой `auto: bash — <начало команды>`.
Повторные снапшоты в пределах `cooldownSeconds` пропускаются, чтобы не тормозить работу;
для разрушительных команд (`rm -rf`, `git reset --hard`, `git clean -fd`) кулдаун игнорируется.

## Конфиг

```yaml
# ~/.dsh/profiles/<profile>/cordis.patch.yml
- id: dsh-snapshots
  config:
    roots:
      - '~/Games/MyGame'
    storeDir: '~/.dsh/snapshots'
    keep: 30
    autoSnapshot: true
    cooldownSeconds: 45
    exclude: ['.git/', 'node_modules/', '.DS_Store', '*.log']
```

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `roots` | `[]` = рабочая папка сессии | какие каталоги снапшотить |
| `storeDir` | `~/.dsh/snapshots` | где лежат теневые репозитории |
| `keep` | `30` | сколько снапшотов хранить на проект |
| `autoSnapshot` | `true` | снимать снапшот перед изменяющими вызовами |
| `cooldownSeconds` | `45` | пауза между авто-снапшотами одного проекта |
| `exclude` | см. выше | доп. шаблоны в `info/exclude` теневого репо |

## Ограничения

- `--clean` удаляет только обычные файлы; каталоги, опустевшие после удаления, остаются.
- Снапшот — это рабочее дерево на момент вызова, а не история правок: нет веток,
  мержа и диффов по коммитам (за диффом — `/rollback` без `--clean` показывает счётчик
  изменённых путей в ответе).
- Большие бинарники каждый раз копируются целиком: для проектов с гигабайтами ассетов
  добавьте их в `exclude`.
- Git обязателен в `PATH`; без него плагин пишет предупреждение и ничего не делает.

## Удаление

```bash
rm -rf ~/.dsh/snapshots
```
